# AI 应用开发技能图谱

## 岗位的三种形态

"AI 应用开发"这个岗位名称在不同公司指代的工作差异很大，大致分三类：

**第一类，LLM 应用开发。** 基于大模型 API 做产品，核心工作是 Prompt 工程、RAG 检索增强、Agent 编排、效果评测。技术栈以 Python + LangChain/LlamaIndex + 向量库为主，对模型训练要求不高，但对工程落地能力要求高。

**第二类，算法工程化。** 把算法团队的模型部署成服务，核心工作是推理优化、服务封装、性能调优。需要熟悉推理框架（vLLM、TensorRT）、容器化、GPU 资源管理。

**第三类，平台与基础设施。** 做模型服务中台、评测平台、数据流水线。偏后端和架构，需要较强的分布式系统能力。

投递前要看清楚 JD 属于哪一类，三者的准备方向差别很大。

## 核心技术栈

### 编程语言

Python 是绝对主力。除此之外，工程化程度高的团队会要求 Go 或 Java 做服务层。

Python 方面要掌握的不只是语法：异步编程（asyncio）、类型注解、包管理、虚拟环境、常见性能陷阱（GIL、列表操作复杂度）。

### 大模型调用

这是最基础的一层，但细节很多：

- **接口协议**：OpenAI 兼容接口已成为事实标准，掌握 chat completions、embeddings 两类接口
- **参数理解**：temperature、top_p、max_tokens 的影响，frequency_penalty 的作用
- **流式输出**：SSE 协议，如何处理分块返回
- **Function Calling**：工具定义格式、并行调用、结果回传
- **成本控制**：token 计费方式、上下文长度对成本的影响、缓存策略
- **错误处理**：超时、限流、重试、降级

### RAG 检索增强

这是 AI 应用岗最核心的技能，几乎必考。完整链路包括：

| 环节 | 关键技术点 |
|---|---|
| 文档解析 | PDF（含扫描件 OCR）、Word、HTML、Markdown 解析 |
| 切分 | 固定长度、递归字符、语义切分；chunk_size 与 overlap 的权衡 |
| 向量化 | embedding 模型选择、维度、批量调用、归一化 |
| 存储 | 向量库选型（Chroma/FAISS/Milvus/Qdrant）、索引类型 |
| 召回 | 向量召回、关键词召回（BM25）、混合检索 |
| 重排 | cross-encoder、LLM 重排、规则重排 |
| 生成 | context 拼接、prompt 约束、引用标注 |
| 评测 | recall@k、MRR、答案准确率、忠实度 |

面试中如果只能深入一个方向，选 RAG。

### Agent 编排

Agent 是 RAG 之上的进阶能力，核心是让模型自主决定调用哪个工具、按什么顺序。

需要掌握：

- **ReAct 范式**：思考、行动、观察的循环
- **工具设计**：schema 定义、描述写法、边界说明
- **编排框架**：LangGraph 的状态图、节点、边、条件路由
- **状态管理**：多轮对话的持久化（checkpointer）、上下文裁剪
- **可控性**：中断、人工确认、最大轮次限制、超时控制
- **可观测**：每步的输入输出记录、成本统计

### Prompt 工程

不是"会写提示词"这么简单，工程化的 Prompt 管理包括：

- 版本管理（prompt 存在配置文件还是代码里）
- 模板化（变量注入、多语言）
- 结构化输出（JSON schema 约束、解析容错）
- 评测（同一 prompt 在不同模型上的表现对比）

### 后端与部署

AI 应用终究要作为服务提供，这部分决定你能不能独立交付：

- **Web 框架**：FastAPI（异步、类型校验、自动文档）
- **接口设计**：RESTful、流式接口、鉴权
- **数据存储**：关系库（PostgreSQL/MySQL）、缓存（Redis）
- **部署**：Docker 镜像构建、docker-compose、Nginx 反代
- **可观测**：日志、指标、链路追踪
- **CI/CD**：基本的自动化构建与发布

### 评测能力

这是区分"做过 demo"和"做过产品"的关键。要能回答：

- 怎么定义"效果好"
- 用什么数据集评测
- 人工评测和自动评测怎么结合
- 上线后怎么监控效果衰减

## 技能优先级

如果时间是有限的，按这个顺序投入：

1. **Python 与后端基础**（必备，没有这个其他都白搭）
2. **RAG 完整链路**（岗位核心，面试必考）
3. **Agent 编排**（加分项，能显著提升竞争力）
4. **评测方法**（区分度最高的加分项）
5. **部署与运维**（能证明可独立交付）
6. **Prompt 工程**（相对容易，随项目积累）

## 常见的能力误区

**误区一：只学框架不学原理。**
会用 LangChain 的 API 不等于理解 RAG。面试官问"为什么切分要用重叠"，答不上来说明只是调包。

**误区二：只做 demo 不做工程。**
跑通一个问答 demo 很容易，但加上错误处理、超时、限流、日志、评测之后，才是工程项目。简历上写"实现了一个 RAG 系统"和"实现了带 MD5 去重、幂等灌库、检索为空兜底的 RAG 系统"，分量完全不同。

**误区三：忽视传统后端能力。**
很多人以为 AI 应用岗不需要后端，实际上面试照样问数据库索引、并发、缓存。AI 只是业务逻辑的一部分。

**误区四：不做评测。**
没有评测就没有优化方向。能说清"我怎么衡量效果"的候选人，通常被认为更有工程素养。

## 学习路径建议

对于有 Python 基础、想转 AI 应用开发的人，一个可行的路径是：

1. 先用现成框架跑通一个 RAG 问答（1 周）
2. 把每个环节拆开自己实现一遍：解析、切分、向量化、检索、拼接（2 到 3 周）
3. 加上多轮对话和工具调用，做成 Agent（2 周）
4. 补上评测、日志、部署（1 到 2 周）
5. 把整个过程整理成一个可以讲 30 分钟的项目

这个路径的价值在于第 2 步：拆开自己实现一遍，才能在被追问细节时答得出来。
