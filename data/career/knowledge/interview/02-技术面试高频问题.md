# 技术面试高频问题与答题框架

## 技术问题的四种类型

技术面的问题看似随机，实际可以归为四类，每类的考察点和答题方式不同：

| 类型 | 典型问法 | 考察点 | 答题结构 |
|---|---|---|---|
| 原理题 | "介绍一下 Transformer 的注意力机制" | 知识广度与准确性 | 结论先行 + 关键细节 |
| 选型题 | "为什么用 Chroma 不用 FAISS" | 技术判断力 | 对比维度 + 场景约束 |
| 设计题 | "设计一个文档问答系统" | 系统性思维 | 分层拆解 + 关键取舍 |
| 场景题 | "检索效果不好怎么排查" | 实战经验 | 假设 + 验证路径 |

## 原理题的答法

原理题最大的陷阱是**背得太全但抓不住重点**。面试官问"介绍一下注意力机制"，不是要你复述论文，而是想确认你理解核心机制。

有效的结构是：**一句话说清是什么 → 关键公式或流程 → 一个实际影响**。

例如回答自注意力：先说"自注意力让序列中每个位置都能直接看到其他所有位置，从而建模长距离依赖"，再说 QKV 的计算方式，最后补一句"这也导致计算复杂度是序列长度的平方，所以长文本需要分块或稀疏化"。最后这句是加分项，它说明你不仅知道原理，还知道它的代价。

## 选型题的答法

选型题没有标准答案，考察的是你是否真的做过权衡。答题的关键是**先给约束，再给结论**。

错误示范："Chroma 更轻量，所以我们用了 Chroma。"——太笼统。

正确示范："我们的场景是单机部署、数据量在万级、需要本地持久化，Chroma 支持嵌入式运行不需要额外服务，所以选了它。如果数据量到百万级或者需要分布式，我会换成 Milvus，但那样的运维成本对这个项目不划算。"

这个答法的结构是：场景约束 → 选择的理由 → 边界条件（什么情况下会换）。第三部分最能体现判断力。

## 设计题的答法

设计题不要一上来就说技术栈。正确的顺序是**澄清需求 → 分层设计 → 说明取舍**。

以"设计一个文档问答系统"为例：

**第一步，澄清。** 问清楚文档规模、更新频率、是否需要多轮、对延迟的要求。这一步很多人省略，但它是加分项——说明你知道需求决定设计。

**第二步，分层。** 离线部分（文档解析、切分、向量化、入库）和在线部分（查询改写、召回、重排、生成）。

**第三步，取舍。** 指出关键决策点，例如"切分粒度大会丢失细节，小会破坏上下文，所以按语义边界切并保留重叠"。

## 场景题的答法

场景题通常是"效果不好怎么办"，考察排查思路。答题框架是：**列可能原因 → 给验证方法 → 给改进手段**。

以"RAG 回答不准确"为例，可能原因可以从链路两端拆：

召回侧：切分不合理导致语义割裂、embedding 模型与语料不匹配、top-k 太小漏掉正确片段、没有重排导致噪声靠前。

生成侧：context 拼接方式不当、prompt 没有约束"仅基于资料回答"、模型本身能力不足。

验证方法：先把命中的片段打印出来人工看，如果片段本身就不对，问题在召回；如果片段对但答案错，问题在生成。

这个"先定位是召回还是生成"的判断，是区分有实战经验和只背过概念的关键。

## RAG 相关的高频问题

**"你的切分策略是什么？"**
要说清 chunk_size、overlap 的取值和理由，以及中文场景下的特殊性（按标点切分比按字符切分更合理）。

**"为什么需要重排？"**
向量召回是双塔模型，query 和文档分别编码，交互不充分；重排模型（cross-encoder 或 LLM）能同时看到 query 和文档，精度更高但更慢，所以放在召回之后做。

**"怎么评估 RAG 效果？"**
分两层：检索层看 recall@k 和 MRR，生成层看答案准确率和忠实度（是否忠于资料）。没有标注数据时，可以人工抽检加 LLM 打分。

**"幻觉怎么控制？"**
三种手段：prompt 约束、检索为空时明确拒答、生成后做事实校验。要强调"检索不到就不答"比"硬答"更重要。

## Agent 相关的高频问题

**"ReAct 和 Function Calling 有什么区别？"**
ReAct 是让模型输出"思考-行动"的文本再由框架解析，Function Calling 是模型直接返回结构化的工具调用。后者更稳定，前者更灵活。

**"工具太多模型会不会选错？"**
会。解决方式是分层路由（先分类再选工具）、工具描述写清楚使用边界、必要时用专门的工具选择中间件。

**"多轮对话的上下文怎么管理？"**
要讲清"存"和"省"是两件事：checkpointer 负责持久化，裁剪或摘要负责控制每次送模型的长度。裁剪时要注意工具调用和结果必须成对，否则 API 会报错。

## 不会答的时候怎么办

遇到完全不会的问题，三种处理方式按优先级：

1. **说出你知道的部分**："这块我没有深入用过，但我理解它的原理是 xxx，如果理解有偏差请您指正。"
2. **说出排查思路**："我没遇到过这个具体问题，如果是我排查，我会先 xxx 再 xxx。"
3. **坦诚承认**："这个我不了解，回去我会补上。"

最差的是编造。面试官通常比你更熟悉这个领域，编造一旦被追问就会崩盘。

## 答题的三个通用原则

**结论先行。** 先给答案再解释，不要铺垫太久。面试时间有限，面试官需要快速判断对错。

**主动暴露边界。** 说"这个方案在 xxx 条件下成立"，比说"这个方案很好"更可信。

**留钩子。** 每个回答留一个可以继续深入的点，把面试引导到你准备好的方向。
